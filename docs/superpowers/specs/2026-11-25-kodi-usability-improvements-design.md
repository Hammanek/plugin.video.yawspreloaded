## Intent and invariants

Investigate lifecycle behavior before changing it. Keep all successful Webshare download/history and TMDB watchlist characteristics, identity/session/scope/generation locking, complete snapshot rules, task ownership and exactly-once Kodi completion. Only explicit category/list actions trigger new network work. All test data is synthetic and all diagnostics use isolated profiles; never alter or forcibly stop the real main Kodi during development. Do not expose real credentials, sessions, user data or copy anything into git beyond intended source/resources.

Existing IDs/routes stay unchanged except explicitly approved:
- additive `refresh=1` watchlist action and `tmdb_discovery`;
- addition of `discovery_native_wall` boolean in TMDB settings;
- removal of obsolete `db`/`searchdb` actions and the Backup DB main-menu item. Legacy invocations then fall back to the ordinary root directory without remote DB work.
- discovery takes **position 1**; existing order of the remaining root entries is preserved otherwise.

## Scope

1. **Shutdown diagnosis first.** Inspect the real shutdown log: save stops followed by CPythonInvoker thread warning. Reproduce only in portable Kodi 21.2 with synthetic settings and controlled localhost XML/JSON; record request entered, delay, abort observed, result parsed, session closed, request completed and owner close returned. Test idle and meaningful delayed metadata/watchlist work. If a code defect is reproduced, add a failing unittest before changing responsible code; otherwise document checked negative evidence, do not blindly change timeouts or daemon semantics.
2. **Metadata adapter.** Replace current `ListItem.setInfo("video", data)` with one helper using `getVideoInfoTag()`: title, mediatype, plot, year, genres as required list, rating, season, episode, duration seconds and first-aired. Preserve current numeric values. Explicitly use `setFirstAired`; genre strings split on ` / ` if necessary. `runtime.get...` never has a made-up method. Fallback for old test doubles without the method calls documented `setInfo("video", info)` once. No other label/artwork/play semantics change.
3. **Explicit watchlist refresh.** Existing watchlist receives a bottom **Obnovit** row with new optional `refresh=1`. Keep old snapshot until complete validated save. Use the current operation client and captured account/session/language/generation. Failure leaves last complete data durable and uses normal listing-error reporting. Successful immediate refresh does not queue an unnecessary duplicate background fetch. Non-manual warm/cold calls keep measured behavior.
4. **UX labels and localization.** Existing snapshot carries a localized local-cache status. A valid zero-result Webshare page shows an explanatory row without modifying page/auth/query behavior. Allocate **30438 Refresh**, **30439 Local cache**, **30440 No matching files found** in English, Czech and Slovak, and **30441 Discover**, **30442 Popular**, **30443 Top rated**, **30444 Use native wall in Objevit** in all three catalogs.
5. **Objevit.** Add a separate handler under `tmdb_discovery` and an independent `discovery_ui.py`. Root order is exactly **Objevit → Vyhledávání → Chci si stáhnout → Historie stahování → Nastavení → TMDB Watchlist**. Categories: `/movie/popular` (`popular_movies`), `/tv/popular` (`popular_shows`), `/movie/top_rated` (`top_rated_movies`), `/tv/top_rated` (`top_rated_shows`). The TMDB API key is required but a personal account/session, account resolution or watchlist snapshot is not. A selected category costs at most one list request and at most one shared genre lookup, no continuous pagination, metadata/trailer prefetch or background registration. Unknown modes are local failures, never dynamic path format strings.
6. **Reversible presentation.** `discovery_native_wall=false` (chosen default) uses a Netflix-inspired native Kodi window with four category controls, selected item's backdrop, title/year/genre/rating/blurb, visible poster focus and no unnecessary animation. The custom native control/window and its focused tests reside in `discovery_window.py` and use a factory so they can be tested without lying about available Kodi APIs. `discovery_native_wall=true` returns to the normal plugin InfoWall flow. Style changes affect the next Objevit opening only and do not change watchlist views or require reinstall. Both layers reuse the same catalog data and Webshare route. All loading/empty/error and back/keyboard cases must complete at most once.
7. **Result semantics.** Result cards show localized title/original alternative where appropriate, release year, genre list, rating, overview and artwork. Main selection always goes to existing Webshare search with **sort=largest**; original-title search uses existing 30414 command when applicable. No autoplay, watched mutation, snapshot mutation or silent installer/deleting content. `client.get` occurs only on a valid explicit category, then bounded CDN downloads are left to Kodi. InfoTag is applied identically to the white-label info data used by the normal list and custom hero.
